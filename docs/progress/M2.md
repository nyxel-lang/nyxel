# M2 语义分析与代码生成：开发日志

## 2026-10-31 · 语义分析的设计文档

- 用户问语义分析要做什么，先用 Spawner.nyxel 的 `OnTriggerEnter` 讲了它要回答的问题：名字指向哪个符号、表达式的类型、收窄、`?? return`、字面量定型，以及为什么不交给 Roslyn（`let x: float = 1 / 2` 翻译前就要知道类型，`let` 重新赋值 C# 不会报）。
- 写了 design/semantic-analysis.md：
  - 符号一套接口、两种来源：源码符号和包装 Roslyn 符号的元数据符号；读元数据用一个只有引用的 `CSharpCompilation`，后端编译时往里加语法树。
  - 分五遍：声明、导入、类型头、成员签名、函数体。成员的类型都写在签名上（ADR-0006），所以函数体互相独立。
  - `BindExpression` 带期望的类型，字面量、lambda、集合字面量、当值用的分支都靠它。
  - 重载决议和类型推断自己实现 C# 的规则，和 Roslyn 做对照测试（比较选中方法的 `GetDocumentationCommentId()`）。不选试探性绑定：lambda 的推断和 Nyxel 的函数体交织，字面量定型和收窄的规则不同，报错要翻译。
  - 收窄在绑定时带着流状态做；确定赋值、可达性在绑定树上另走一遍。
  - 第一条线的范围和验收程序（hello world、FizzBuzz、斐波那契、素数筛、排序）。
- 设计时发现两条还没定的语言规则，第一条线就会碰到：程序入口；局部变量和外层同名。Roslyn 5.9 确认 C# 的规则：内层块同名是 CS0136，并列的块可以，C# 8 起 lambda 里可以同名。
- 第二十九轮讨论，两项都按推荐，写进 ADR-0036：入口同 C#，任意类型里没有 `self` 的 `Main`；一个函数里一个名字只指一个变量，lambda 也不例外（比 C# 严）。由此推出的一条细节：局部变量从声明处开始可见，块结束后可以再声明同名的变量（C# 不行）。

## 2026-10-31 · 第一条线：Binder、降级、后端、`nyxel run`

- 先做最细的一条：hello world 从符号一路走到能运行，验证架构，再在第一条线的范围里加宽。
- 符号（`Symbols/`）：
  - 元数据只包定义，构造类型由 Nyxel 自己构造、自己替换成员（`ConstructedNamedTypeSymbol` + `TypeMap`），所以 `List<Slime>` 这种类型实参是 Nyxel 类型的也能表示；嵌套在泛型里的类型按“所有外层的类型实参 + 自己的”构造。
  - 数组的成员走基类 `System.Array`，`IList<T>` / `IReadOnlyList<T>` 作为接口。
- Binder（`Binding/`）：`Declarer` 做前四遍，`MethodBinder` 做函数体；函数里的作用域是一个栈，同名检查（ADR-0036）就是声明时查整个栈。语义诊断 NYX2001–NYX2053。
- 实现时发现的语言问题，没有自己定：`Math.Max(1, 2.5)` 按 ADR-0013“参数类型决定字面量的类型”会让 `Max(float, float)` 也适用，和 `Max(double, double)` 分不出好坏。先改成两步：完全按 C# 选；没有一个适用时，小数字面量才能变成 `float` / `decimal`。几个都适用时字面量该是什么类型，记进 STATUS，要和用户讨论。
- 对照测试抓到的 bug：没有上下文的 `3000000000` 应当是 `uint`（ADR-0007），原来跳过了 `uint`。`float` 常量折叠时三元表达式把它提升回了 `double`。
- 降级（`Lowering/`）：列跟踪的文本写出器；类型都写 `global::` 全名；数值转换都写成强制转换，让 C# 选的就是 Binder 选的；`for` 的区间两端只求一次值，循环变量每次迭代是新的。
- 后端：降级出的 C# 加进读元数据的那个 `CSharpCompilation`，pdb 嵌入 .nyxel。Roslyn 的错误映射回 .nyxel，报 NYX2053。
- CLI：`nyxel build [--exe] [--emit-cs] [-o]`、`nyxel run [-- args]`；引用运行中的 .NET 的共享框架。
- 验收：tests/Nyxel.Compiler.Tests/Programs/ 五个程序的输出和 C# 快照；运行时异常的堆栈是 `Crash.nyxel:line 4`。断点要在 VSCode 里手动验证，还没做。
- 坑：
  - Roslyn 的程序集里有一个全局命名空间 `Roslyn`（`Roslyn.Utilities`），`using Roslyn = Microsoft.CodeAnalysis;` 的别名会冲突，改叫 `CodeAnalysis`。
  - C# 14 里 `field` 是属性访问器里的上下文关键字，主构造函数的参数不能叫 `field`。
  - `ImmutableArray` 上的 `SequenceEqual` 有二义性，写成 `Enumerable.SequenceEqual(...)`。
  - 测试项目会把 Programs/*.g.cs 当源码编译（快照里的 `Main` 还会和测试 SDK 生成的入口冲突），csproj 里 `Compile Remove="Programs/**"`。
  - 重新抛出 `TargetInvocationException` 的内层异常要用 `ExceptionDispatchInfo.Capture(inner).Throw()`，`throw inner` 会冲掉原来的堆栈。
  - 又在 heredoc 里写了含 `\n` 的 python 补丁，被折叠成真的换行（AGENTS.md 早写着）。C# 测试里的多行字符串改用原始字符串 `"""`，补丁一律用 Write 写成文件。
- 验证：11 + 908 个测试、19 项高亮快照全绿，format 通过。

## 2026-11-02 · 调用里的字面量跟着有类型的实参（ADR-0037）

- 第三十轮讨论，定了 B：`Resolve` 先走一步 `LiteralsFollow`（有类型的实参只认原样传进去，字面量放得进任何装得下它的数值类型，比较时数值类型都一样好、比装箱好），选不出唯一一个再走原来的两步（C# 的规则；都不适用时小数字面量能变成 `float` / `decimal`）。
- 讨论前用 Roslyn 探针确认了 C# 的选择：`Math.Max(f, 0.5)` 是 double 的那个；`f.Equals(0.5)`、`f.CompareTo(0.5)`、`Array.IndexOf(floats, 0.5)` 都选到了 `object` 参数的重载（永远 false、运行时抛异常、永远 -1）；`Math.Max(b, 1)`（byte）是 CS0121。
- 对照测试分两组：和原样的 C# 比；字面量跟着实参的，和补上后缀的 C# 比（`0.5f`、`(byte)1`、`0.5m`）。
- 顺手修了二义性的诊断：原来列的是前两个适用的重载（`Math.Max(ulong, int)` 报 decimal 和 double），改成两个谁也不比谁好的（decimal 和 float，同 Roslyn）。
- 坑：`dotnet test` 不会更新 build/dotnet/bin/Nyxel.Cli 里那份编译器；用 CLI 试新行为前先 `dotnet build src/Nyxel.Cli`（或者跑 `tools\build.cmd`）。
- 验证：11 + 921 个测试、19 项高亮快照全绿，format 通过。
