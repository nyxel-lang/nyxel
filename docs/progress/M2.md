# M2 语义分析与代码生成：开发日志

## 2026-10-31 · 语义分析的设计文档

- 用户问语义分析要做什么，先用 Spawner.nyxel 的 `OnTriggerEnter` 讲了它要回答的问题：名字指向哪个符号、表达式的类型、收窄、`?? return`、字面量定型，以及为什么不交给 Roslyn（`let x: float = 1 / 2` 翻译前就要知道类型，`let` 重新赋值 C# 不会报）。
- 写了 design/semantic-analysis.md：
  - 符号一套接口、两种来源：源码符号和包装 Roslyn 符号的元数据符号；读元数据用一个只有引用的 `CSharpCompilation`，后端编译时往里加语法树。
  - 分五遍：声明、导入、类型头、成员签名、函数体。成员的类型都写在签名上（ADR-0006），所以函数体互相独立。
  - `BindExpression` 带期望的类型，字面量、lambda、集合字面量、当值用的分支都靠它。
  - 重载决议和类型推断自己实现 C# 的规则，和 Roslyn 做对照测试（比较选中方法的 `GetDocumentationCommentId()`）。不选试探性绑定：lambda 的推断和 Nyxel 的函数体交织，字面量定型和收窄的规则不同，报错要翻译。
  - 收窄在绑定时带着流状态做；确定赋值、可达性在绑定树上另走一遍。
  - 第一条线的范围和验收程序（hello world、FizzBuzz、斐波那契、素数筛、排序）。
- 设计时发现两条还没定的语言规则，第一条线就会碰到：程序入口；局部变量和外层同名。Roslyn 5.9 确认 C# 的规则：内层块同名是 CS0136，并列的块可以，C# 8 起 lambda 里可以同名。
- 第二十九轮讨论，两项都按推荐，写进 ADR-0036：入口同 C#，任意类型里没有 `self` 的 `Main`；一个函数里一个名字只指一个变量，lambda 也不例外（比 C# 严）。由此推出的一条细节：局部变量从声明处开始可见，块结束后可以再声明同名的变量（C# 不行）。
