# M2 语义分析与代码生成：开发日志

## 2026-10-31 · 语义分析的设计文档

- 用户问语义分析要做什么，先用 Spawner.nyxel 的 `OnTriggerEnter` 讲了它要回答的问题：名字指向哪个符号、表达式的类型、收窄、`?? return`、字面量定型，以及为什么不交给 Roslyn（`let x: float = 1 / 2` 翻译前就要知道类型，`let` 重新赋值 C# 不会报）。
- 写了 design/semantic-analysis.md：
  - 符号一套接口、两种来源：源码符号和包装 Roslyn 符号的元数据符号；读元数据用一个只有引用的 `CSharpCompilation`，后端编译时往里加语法树。
  - 分五遍：声明、导入、类型头、成员签名、函数体。成员的类型都写在签名上（ADR-0006），所以函数体互相独立。
  - `BindExpression` 带期望的类型，字面量、lambda、集合字面量、当值用的分支都靠它。
  - 重载决议和类型推断自己实现 C# 的规则，和 Roslyn 做对照测试（比较选中方法的 `GetDocumentationCommentId()`）。不选试探性绑定：lambda 的推断和 Nyxel 的函数体交织，字面量定型和收窄的规则不同，报错要翻译。
  - 收窄在绑定时带着流状态做；确定赋值、可达性在绑定树上另走一遍。
  - 第一条线的范围和验收程序（hello world、FizzBuzz、斐波那契、素数筛、排序）。
- 设计时发现两条还没定的语言规则，第一条线就会碰到：程序入口；局部变量和外层同名。Roslyn 5.9 确认 C# 的规则：内层块同名是 CS0136，并列的块可以，C# 8 起 lambda 里可以同名。
- 第二十九轮讨论，两项都按推荐，写进 ADR-0036：入口同 C#，任意类型里没有 `self` 的 `Main`；一个函数里一个名字只指一个变量，lambda 也不例外（比 C# 严）。由此推出的一条细节：局部变量从声明处开始可见，块结束后可以再声明同名的变量（C# 不行）。

## 2026-11-04 · review 第二批：`static func`、`struct enum` / `class enum` 写明（ADR-0039）

- 第三十二轮讨论，两项都推翻旧 ADR 里的一个默认：

  - 带数据的 enum 默认在堆上，短的写法恰好是分配的那个。用户选 D：必须写明 `struct enum` 或 `class enum`，和 class / struct 之间没有默认一样（推翻 ADR-0024 决策 6 的默认方向）。

## 2026-11-06 · Binder 加宽第一步：空值和收窄

- 符号：`NullableTypeSymbol`（`Enemy?`、`int?` 一种表示，按底层类型缓存）、`NullTypeSymbol`（`null` 字面量）。读元数据按 C# 的可空标注；成员类型走 `GetMemberType`，没标注的程序集最外层当 `T?`；没约束的 `T?` 代入值类型是 `T`。源码里 `T?` 不再报 NYX2001，`Nullable<int>` 也是 `int?`。
- 转换：`T` → `T?`、`null` → `T?`；`T?` 不转成 `T`（NYX2058，消息给出检查的写法）。重载决议里 `string` 和 `string?` 算同一个类型（`IsSameRuntimeType`），否则 `Console.WriteLine(s)` 第一步（ADR-0037）就选不中。
- 流状态：`MethodBinder.Nulls.cs` 的 `_flow`（局部变量 / 参数 → 收窄后的类型）；条件绑定出“成立 / 不成立”两个状态，`if`、`while`、`for`、`and` / `or` / `not` 按 semantic-analysis.md 的规则传递和汇合。读变量时节点的 `Type` 就是收窄后的类型，降级按需插入强制转换。
- 新写法：`== null`（降级成 `is null`）、`is` / `is not`、`?.`（整条链在占位接收者上重新绑定，降级时占位写成空，拼出 C# 的 `a?.B.C()`）、`??`（右边数字跟着左边的类型）、`?? return / break / continue`（只在整条语句的值上，降级成先检查再取值）、`?? throw`、`??=`、`throw` 语句、`new array<Enemy>(n)` 的检查（ADR-0023）。诊断 NYX2057–2065。
- 没定的四处先按最严的报错（`int?` 不提升运算符、`int?` 的 `.Value` 等不能用、赋非空值不收窄、对不会是 null 的值写 `== null` 等报错），连同“没标注的程序集只管最外层”一起列给用户讨论（STATUS“悬而未决”）。
- 测试：`NullSafetyTests`（类型、元数据标注——用 Roslyn 现编一个关着 / 开着可空标注的程序集、收窄接受的 25 种写法、23 个错误）；Programs/Nulls.nyxel（链表遍历、`?.`、`?? return`、`?? continue`、`is`、`??=`、`int?` 收窄）。原有五个程序的 C# 快照没变。
- 坑：
  - Bash heredoc 里的 python 又把 `"\n"` 折叠成真的换行（AGENTS.md 早写着）；补丁脚本一律 Write 到 build/tmp。
  - `ConditionalMemberAccessExpression` 和普通成员访问是同一个语法类，`a?.B.C` 解析成 `(a?.B).C`（左结合）；C# 的短路范围要在绑定时沿着“接收者链”找最深的 `?.` 实现，括号截断。
  - 字段默认私有：测试程序里 `let value: int` 被别的类型读要写 `public`。
- 验证：11 + 1005 个测试、19 项高亮快照全绿，format 通过。

## 2026-11-09 · 空值的五处细节定稿（ADR-0041）

- 第三十四轮讨论：上一轮实现时按最严的方式处理的五处，用户选了 1A 2C 3A 4B 5A：赋了不可能是 null 的值之后当作非空；`int?` 只有 `==` / `!=` 像 C# 那样提升；`T?` 没有成员（`.Value` 也不行）；对不会是 null 的引用类型做 null 检查是警告；没标注的程序集只管最外层。用户追问了 `!=` 的规则：同 C# 的提升，两边都是 null 相等、一边是 null 不等，`a != b` 永远是 `not (a == b)`，所以没有大小比较那种 `hp < 10` 和 `hp >= 10` 同时为 false 的陷阱；要注意的是 `x?.IsDead != true` 在没有 `x` 时也成立。
- 1A 的准确范围写进 ADR：只管是不是 null，`var weapon: Weapon? = new Sword()` 之后是 `Weapon` 不是 `Sword`（同 C#；选项里“变量的类型就是值的类型”说宽了，回复里向用户说明了）。

- 实现：`SourceNamedTypeSymbol` 的 `TypeKind` 按 `struct enum` / `class enum` 给 `Struct` / `Class`，加 `IsDataEnum`、`IsDeclaredEnum`；case 仍是 `SourceEnumCaseSymbol`，多了数据项 `Items`。新节点 `BoundEnumCase`（不带数据的 case 值、`new` 出来的带数据 case）。`BindCreated` 认出 `new E.Case(...)`，数据项当参数走重载决议。新错误码 NYX2088–2090。降级 `LowerDataEnum`，生成的 C# 用 `LanguageVersion.Preview` 编译。
- 探针（build/tmp/probe-union2）：C# 15 的使用方 `switch` 列全不报警告、隐式转换能用；C# 14 的使用方写 union 的模式会报“预览功能”，只能用构造函数和 `TryGetValue`；别的程序集继承 closed 类报 CS9382（C# 14 也是）。
- 坑：C# 15 把 union 值上的模式都当成“是哪个 case 类型”，`x is AiState { __nyxel_Tag: 1 }` 是 CS8121，改成直接比标记，`AiState?` 和 `object` 走生成的 `__nyxel_Is`。Bash heredoc 里的 python 照样会折叠 `\n`，改测试数据用 Edit。
- 验证：见 STATUS。

## 2026-11-12 · match

- 用户确认了带数据 enum 实现时的两处最严处理（不带数据的 case 写 `new` 是错误、case 的数据项不能写默认值），补进 ADR-0046 决策 4（dev 上还没合并，直接补）和 language-reference。
- `match` 进了 Binder：`MethodBinder.Match.cs`。新的绑定节点 `BoundMatchStatement` / `BoundMatchExpression` / `BoundMatchArm` 和九种模式。语句开头的 `match` 当语句，别处当值；分支各自一个作用域，取出的数据是 `let`；`case is T`、`case not null` 收窄；当值用时 `return` / `break` / `continue` 只能在整条语句的值上（同 `?? return`）。`CheckArms` 按顺序算覆盖：到不了的分支 NYX2092，没覆盖全 NYX2091。新错误码 NYX2091–2097。
- 降级：`Lowerer.Match.cs`。语句是 switch 语句（没有 `case _` 时 `default` 抛 `SwitchExpressionException`），值是 switch 表达式；分支会离开的 `let t = match` 先写成 switch 语句给临时变量赋值。switch 里 Nyxel 的 `break` 写成 `goto` 到循环后面的标签。
- 探针（build/tmp/probe-match）：C# 对被覆盖的分支报错误（CS8510、CS8120），所以 Binder 必须先报。union 列全 case 后的 `_`、closed 类列全 case 后的 `_` C# 都不报（前者有“没有值”的状态，后者有 null），`bool` 的 `true`、`false` 之后的 `_` 报；closed 类列全 case 后的 `Condition` 类型模式也报。于是比较、区间、`and`、`not` 这些 Binder 不算覆盖的模式降级时放进 `when`，C# 不看。
- 顺手修了降级的老问题：Nyxel 只查看得见的同名，`if c { let a = 1 }` 之后的 `let a = 2` 在 C# 里是 CS0136，内部错误。`PlanLocalNames` 按 C# 的作用域给后声明的改名（`a_2`），setter 里 `value` 的改名并进来（Structs.g.cs 的 `value_1` 变成 `value_2`）。
- 实现时先按最严处理的几处记在 STATUS“悬而未决”，等用户确认。
- 验证：`tools\build.cmd --test` 全绿，11 + 1358 个测试，高亮快照 19 项；`dotnet format --verify-no-changes` 通过。

## 2026-11-12 · ADR-0048 match 里的空值收窄

- 第四十轮讨论。用户问 `case null -> return` 之后的分支为什么不收窄：实现时取了最保守的做法（ADR 只列了 `case is T`）。对比了和 `if x == null { return }`、C# 可空分析的一致性，用户选了也收窄，写成 ADR-0048，`case not null` 收窄一并写进去。没有 `when`、模式匹配 null 的分支之后才收窄，只管 null。
