## 2026-10-02 · 第五轮讨论：空值与 match

- 空值：违反是编译错误；C# 标注照单全收，无标注的 .NET API 当 `T?`；局部变量和参数的流分析收窄，字段先存局部；`??` 右边可以是 `return` / `throw` / `continue` / `break`；没有强制解包，写 `?? throw`。都按推荐定了。
- match：用户倾向 `case` 开头的写法，并提出两点：能否复用 `->` 而不引入 `=>`；用 `:` 改名（`case Heal(amount: healed)`）和声明的 `名字: 类型` 形状相同、含义不同。都采纳：分支用 `->`（Kotlin `when`、Java 14 switch 的先例，全语言只有一个箭头，lambda 也倾向 `->`）；不支持改名，重名报错，以后需要再加不用冒号的写法。另按 Swift 定了 match 必须穷尽（当语句用也是），“其余不处理”写 `else -> {}`，回复里告知了用户。
- 写进 ADR-0009；language-reference 加了 match、空值两节；VSCode 语法加了 `throw` / `continue` / `break` 和 `true` / `false` / `null`（match 里的 `case` 和 enum 里的一样着色为声明关键字，TextMate 分不清上下文，先不管）。

## 2026-10-02 · 第六轮讨论：循环、运算符、其余模式

- 四项都按推荐定了，写进 ADR-0010：`for x in` + `while`，没有 C 风格 for；区间 `..<`（不含）/ `...`（含），没有单独的 `..`（C#、Rust 与 Kotlin 对 `..` 的理解相反）；逻辑运算用 `and` / `or` / `not`，和模式里的组合词是同一套；去掉 `++` / `--`；类型模式 `is T` + 局部变量自动收窄（和空值收窄同一条规则），`is` 后面只能写类型，其余模式只在 match 里。常量、比较、区间、`or`、`when` 模式随推荐一起定。
- 赋值是语句还是表达式没问到，记为待定，下一轮讨论。
- language-reference 加了循环与区间、运算符、类型检查与收窄三节；VSCode 语法加了 `for` / `in` / `while` / `when`、`and` / `or` / `not` / `is`、`..<` / `...`。

## 2026-10-02 · 第七轮讨论：属性、赋值、命名实参、重载

- 赋值是语句、自己声明的函数不重载（用默认参数），按推荐定了。
- 属性：用户要求不复用 `var`，加专门的关键字。追问后定了 `property` + 访问器块：访问器都带函数体是计算属性，都不带是自动属性（初始值写在类型后，每个访问器一行，可单独加可见性，替代 Swift 的 `private(set)`）；setter 的新值写成 `set(value)`。
- 命名实参：用户选了“可选（同 C#）”，并提出用 `=` 代替 `:`。采纳：因为赋值是语句，实参里的 `count = 3` 没有歧义（Kotlin 也是这个原因）。由此得出全语言规则“冒号后面是类型，等号后面是值”，顺带解决了上一轮改名的同类问题。原推荐“调用 Nyxel 函数必须写参数名”未采纳，记在 ADR 备选里。
- 写进 ADR-0011；ADR-0008 和 language-reference 里的 `name: value` 实参都改成 `name = value`；language-reference 加了属性一节和冒号 / 等号规则。VSCode 语法加了 `property`、`private`，`get` / `set` 只在访问器行首着色（局部变量叫 `set` 不受影响）。

## 2026-10-02 · 第八轮讨论：命名空间与导入、lambda、泛型

- 导入（`import`，每个文件显式列出，无全局 / 隐式导入）和泛型（`<T: 约束>`，多个约束用 `and`，冒号后是类型）按推荐定了。
- lambda：用户提出函数类型写 `func(参数类型) -> 返回类型`、lambda 也以 `func` 开头，就不需要 `void` 占位；以及成员函数也用 `let` 定义。采纳前者：函数类型 `func(A) -> R` / `func(A)`，lambda 是去掉名字的函数 `func(e) { }` / `func(e) = 表达式`（表达式体用 `=`，因为 `func(...) -> X` 的 X 是返回类型），具名函数也允许 `= 表达式` 体。后者没有采纳：CLR 里方法和委托字段是两种东西，`let X = func` 只能悄悄编译成方法，和 `var X: func(...) = ...`（必须是字段）长得一样含义不同。用户同意。
- 顺带定了（回复里告知）：文件结构 `namespace` → `import` → 声明；写 `Func<>` / `Action<>` 给警告；赋值不能作表达式体。
- 写进 ADR-0012；language-reference 加了文件结构、函数类型与 lambda、泛型三节；VSCode 语法加了 `namespace` / `import`。

## 2026-10-02 · 补充讨论：`var self` 的用处

- 用户看示例时问：Spawner 的 SpawnWave 没写 `var self` 也在改 `Wave`，`var self` 真的有用吗。解释了 class 存引用、struct 存数据本身，所以“方法改不改自己”只对 struct 有意义；标出来是为了让 `let` 的 struct 名副其实、挡住在临时副本上修改（Unity 的 `transform.position.Normalize()` 坑）、翻译成 C# 的 `readonly` 成员。用户选择保留。

- 新的待定：C# 里没标 `readonly` 的 struct 方法怎么处理（实现互操作时定）；参数能否重新赋值。
- samples/Combat/Health.nyxel 的 `Apply` 上加了一行注释，指向 Spawner.SpawnWave 作对照。

## 2026-10-02 · 第十二轮讨论：协程

- 先看了 EnginePlayground 的脚本模型：ECS，组件是 unmanaged struct，系统是 `[System]` 静态类的 `Run(World, float dt)`，没有 Behaviour 对象。所以协程设计不能假设脚本一定是对象，samples 里的 `Behaviour` 只是 Unity 式的假想 API。
- 三项都按推荐定了，写进 ADR-0016：`async func` + `await`（能等任何 .NET 可等待对象，恢复后在主线程下一次调度时执行）；调用结果可等待的函数必须写 `await` 或 `launch`，否则编译错误；`launch obj.M()` 绑定 `obj`（引擎基类实现 Nyxel.Runtime 的生命周期接口），销毁后下一次恢复时停止，`finally` / `using let` 照常执行但 `catch` 接不住；热重载前停止所有协程。
- 关键字用 `launch` 不用 `start`：`start` 是常见变量名和 .NET 参数名（`Enumerable.Range(start, count)`）。
- language-reference 加了“协程”一节；VSCode 语法加了 `async`、`await`、`launch`；roadmap M4 记下要实现的运行时部件。

## 2026-10-06 · 错误码编号、空值细节（ADR-0023）

- 错误码编号：用户提出按类别细分号段（语法 1101–1149、其他语言的写法 1150 起）不划算。改成 `NYX1xxx` / `NYX2xxx` 两大段，段内按添加顺序编号，类别只体现在 diagnostics.md 的分表里。ADR-0019 还没合并，直接改了第 4 条。
- 第十八轮讨论，“待定”的第三轮：空值细节，三项都按推荐定：
  - 只有全零合法的元素类型能直接 `new array<T>(n)`，其余用第二个参数 `element` 给出每个元素。Nyxel 的 struct 也算在内（同 ADR-0013 不让写 `new Health()`）。
  - 和 `null` 比较只看引用，翻译成 `is null`，不调用重载的 `==`。
  - `??=` 是语句，字段不收窄。
- 实现：Lexer 加 `??=` 记号，Parser 把它当赋值运算符。其余都是语义规则，留给 M2。FollowCamera 样例用上了 `??=`。

- 坑：EnginePlayground 的托管层是 ECS，`Entity` 是结构体句柄，活没活着用 `world.IsAlive(e)` 查，没有重载 `==`。这是 `== null` 选“只看引用”的一个旁证。

## 2026-10-06 · 枚举（ADR-0024）

- 用户确认 `for (dx, dy) in [(0, 1), (1, 0)]` 里的元组算“直接被解构”，不用写名字。ADR-0022 还没合并，直接补进决策 5，加了一个语法测试（单独提交）。
- 第十九轮讨论，“待定”的第四轮：枚举，八项分两批。前七项按推荐定：
  - 简单枚举的值要写就都写；`enum Tile : byte`；`flags enum` 每个 case 都写值，只有它能位运算（C# 的枚举照 C#）。
  - 没有值为 0 的 case 时，数组要用 `element`。
  - `x is 类型.Case` 只得到 bool。
  - `struct enum` 是带数据枚举的值类型版本，理由是 EnginePlayground 的 ECS 组件要求 `unmanaged`。
  - 带数据枚举的 `==` 比内容。
- 第八项（C# 那边的属性名）：用户选了 PascalCase，又提出定义处也像元组一样用 PascalCase、取数据按元组解构的规则来。比较了两种做法的代价（要补 `_`、加数据项要改 match）后用户确认，取代 ADR-0009 决策 6。
- 实现：
  - Parser：`flags`（只在 `enum` 前面是关键字）/ `struct` 前缀、底层类型（复用 `BaseListSyntax`）、case 的值。读完声明后检查只看声明就能查的规则。
  - 新错误码 NYX1175–1181，其中 1180（`x is Damage.Burn(var a, var s)`）和 1181（`[Flags]`）是 C# 写法。
  - 样例：Damage、Slime、Spawner 的 case 数据改成 PascalCase；Health 用 `case Burn(amount, _)`；Slime 加了用 `is` 的属性；TileMap 的 `Tile : byte`；新样例 Enemies/Turret.nyxel（flags、写明值的 `: byte`、`struct enum`、按位置取数据）。
  - TextMate 语法给 `enum` 前面的 `flags` 上色。
- 验证：8 + 475 个测试全绿，format 通过。探针文件里 13 种错误写法各得一条对应的错误；`flags` 当局部变量名、字段名照常能用。
- 坑：ADR-0009 已在 main 上，不改原文；按 ADR-0018 取代 ADR-0001 一项的先例，只在新 ADR 里写明取代哪一条。
