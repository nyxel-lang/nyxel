# ADR-0007: 注释、数字类型与字面量、if 表达式、字符串插值

- 状态：已接受
- 日期：2026-10-02

## 背景

第三轮讨论：几乎每行代码都会碰到的词法和表达式规则。和用户逐项对比代码后选定。

## 决策

1. **注释**：只有 `//` 行注释。`///` 是文档注释，写在声明前，内容是 Markdown；编译器把它转成 .NET 的 XML 文档文件，C# 引用 Nyxel 程序集时 IntelliSense 照样能显示。没有 `/* */` 块注释。参数和返回值的写法约定（用来对应 XML 的 `<param>` / `<returns>`）在实现文档注释时定，倾向 Swift 的 `- Parameter name:` / `- Returns:`。
2. **内置类型名**：沿用 C# 的别名，含义完全相同：`bool`、`byte`、`sbyte`、`short`、`ushort`、`int`、`uint`、`long`、`ulong`、`float`、`double`、`decimal`、`char`、`string`、`object`。
3. **数值字面量的类型由上下文决定**（Swift 的做法）。
   - 上下文是“这个位置期望的类型”：声明的类型、参数类型、返回类型、二元运算另一侧的操作数等。`let speed: float = 2.5`、`width * 0.5`（`width` 是 `float`）、`new Vector3(0, 1.5, 0)` 里的小数都是 `float`。
   - 没有上下文时与 C# 相同：整数是 `int`（放不下时依次用 `uint`、`long`、`ulong`），小数是 `double`。
   - 混合运算（比如整数乘小数字面量）的完整规则见 ADR-0013。
   - 整数字面量可以用在需要浮点数的地方（`let t: float = 3`），小数字面量不能用在需要整数的地方。值超出目标类型的范围是编译错误（`let b: byte = 300`）。
   - 没有类型后缀（`f`、`d`、`m`、`L`、`u` 都没有）。写了后缀是编译错误，诊断提示删掉。
   - 十六进制 `0xFF`、二进制 `0b1010`、数字分隔符 `1_000_000`、指数 `1e-3` 与 C# 相同。
4. **`if` 和 `match` 可以作为表达式**（Kotlin 的规则）。
   - 分支块里最后一个表达式就是这个分支的值；当表达式用时必须有 `else`。
   - 没有 `?:` 三元运算符。
   - 函数体必须用 `return` 返回值，函数体最后一个表达式不会自动成为返回值。
5. **字符串插值**：`$"HP: {hp}/{maxHp}"`，与 C# 完全相同，包括格式说明符和对齐（`{speed,8:F2}`），以及用 `{{` / `}}` 表示字面的花括号。只有带 `$` 前缀的字符串才插值。普通字符串的转义序列与 C# 相同（`\n`、`\"`、`\\`，以及 `\u` 加四位十六进制的 Unicode 转义）。逐字字符串、原始字符串、多行字符串待定。

## 备选方案

- 注释保留 `/* */`：能跨行，但 C# 的块注释不能嵌套，一个没闭合的 `/*` 会把后面整个文件变成注释，Agent 局部编辑时容易出这种错。编辑器都能“切换行注释”，块注释的价值不大。Zig 也只有 `//`，每一行都能单独做词法分析。
- 文档注释用 C# 的 XML：Agent 最熟，但标签噪音大；Markdown 本身读起来就是文档，转成 XML 是编译器的事。
- 类型名用 Swift 的 `Int`：Swift 的 `Int` 是 64 位，同一个名字含义不同。用 Rust 的 `i32` / `f32`：不符合 ADR-0006 的关键字风格。
- 字面量规则同 C#（`2.5` 一律是 `double`，`float` 写 `2.5f`）：C# 程序员熟悉，但游戏代码几乎全是 `float`，满屏 `f` 后缀，漏写就报错。随上下文定型、无上下文时默认 `float`：游戏代码更顺手，但 `let x = 2.5` 在 C# 里是 `double`、在 Nyxel 里是 `float`，同样写法含义不同。
- 保留 C# 的 `if` 语句 + `?:`：熟悉，但三元运算符一嵌套就难读，而且和 `if` 表达式并存就是两种写法。Rust 的规则（函数最后一个表达式自动返回）：最简洁，但在没有分号的语言里，函数末尾单独一行 `x` 很像普通语句，读者找不到值从哪里返回。
- 插值用 `"${hp}"`（Kotlin / TypeScript）：所有字符串都插值，普通字符串里的 `$` 要考虑转义，Kotlin 还允许 `$hp` 省略括号，是两种写法。用 `"\(hp)"`（Swift）：写法少见，格式说明符要另定。

## 后果

- 字面量定型要在语义分析里做（需要知道期望类型），不能在词法阶段决定。
- 写 C# 习惯的 Agent 会写出 `2.5f`、`?:`、`/* */`，都会得到编译错误和明确的修改提示，不会悄悄改变含义。
- `match` 的完整写法和模式语法在模式匹配那一轮定。
