# ADR-0011: 属性、赋值、命名实参、重载与默认参数

- 状态：已接受
- 日期：2026-10-02

## 背景

第七轮讨论。属性是 .NET API 的常见形态（`transform.Position`），C# 接口也只能声明属性不能声明字段，Nyxel 需要能声明属性。另外要定：赋值是语句还是表达式，调用时实参要不要写参数名、怎么写，以及自己声明的函数能不能重载。

用户的修改：属性不复用 `var`，用专门的关键字；命名实参不用冒号，改用等号。由此得出一条通用规则（决策 1）。

## 决策

1. **冒号后面是类型，等号后面是值。** 这是全语言的规则：`var hp: int = 100`、参数 `count: int = 1`、继承 `class Slime : Behaviour`、调用 `Spawn(count = 3)`。唯一的例外是插值字符串里的格式说明符 `{speed:F2}`，它是字符串内部的格式写法，同 C#。
2. **属性用 `property` 关键字**，`var` / `let` 只声明字段。
   ```nyxel
   public property IsDead: bool {          // 计算属性：访问器带函数体
       get { return self.hp <= 0 }
   }

   public property Hp: int {
       get { return self.hp }
       set(value) { self.hp = Math.Clamp(value, 0, self.maxHp) }
   }

   public property Score: int = 0 {        // 自动属性：访问器都不带函数体，由编译器存值
       get
       private set
   }
   ```
   - 访问器要么都带函数体（计算属性），要么都不带（自动属性，初始值写在类型后面）。
   - 每个访问器一行，可以单独加可见性（`private set`），规则同 C#。
   - setter 收到的新值在括号里命名：`set(value)`。C# 里隐式出现的 `value` 在 Nyxel 里必须写出来。
   - 访问器里的 `self` 隐式可用，和 `init` 一样；静态属性写 `static property`。
   - 接口里声明属性：`property Health: int { get }`。
   - 翻译：计算属性和自动属性都是 C# 属性；`var` / `let` 是 C# 字段（引擎组件靠字段布局，不能变成属性）。
   - 怎么选：默认用字段。实现接口的属性、对外只读而对内可写、值需要计算时，用属性。
3. **赋值是语句**，不产生值：不能写 `a = b = 0`，不能写在条件里（`if hp = 0` 是编译错误，诊断问是不是想写 `==`）。复合赋值 `+=` 等同样是语句。
4. **命名实参写 `名字 = 值`**：`self.Spawn(kind = EnemyKind.Slime, count = 3)`。
   - 写不写参数名由调用者决定。混用规则同 C#（位置实参在前；命名实参的位置规则同 C#），调用 .NET 方法也一样。
   - 因为赋值是语句，实参里的 `count = 3` 不会被当成赋值。
   - 写成 C# 的 `count: 3` 是编译错误，诊断提示改成 `count = 3`。
5. **自己声明的函数不能重载**：同一个类型里函数不能同名，和 `init` 的规则一致（ADR-0008）。
   - 需要多种用法时，起不同的名字，或者用默认参数。默认参数写成 `count: int = 1`，规则同 C#（默认值必须是编译期常量，写在参数列表最后）。
   - 例外：`override` .NET 基类里本来就重载了的方法，以及实现接口里重载了的方法。调用 .NET 的重载方法照常，由 Roslyn 决定调哪一个。

## 备选方案

- **属性复用 `var`，靠类型后面是 `=` 还是 `{` 区分**（Swift）：少一个关键字，但字段和属性在 C# 里是两种东西（布局、接口、序列化都不一样），用户要求一眼可分。**关键字用 `prop`**：是缩写，不符合 ADR-0006 的关键字规则。**分开的 `get` / `set` 声明**（JS / TS）：没有自动属性，一个属性拆成两处，两处可能写得不一致。
- **setter 里的新值隐式叫 `value`**（C#）：少写一个词，但它是凭空出现的名字，和 ADR-0008 “名字的来源看得见”的方向相反。
- **赋值是表达式**（C#）：可以 `a = b = 0`，但 `if (x = 5)` 是 C 家族的经典 bug；和去掉 `++` 的理由相同。
- **命名实参用冒号**（C#、Swift）：熟悉，但和声明里的 `名字: 类型` 形状相同、含义不同（用户指出）。Kotlin 和 Python 用 `=`。
- **调用 Nyxel 函数时必须写参数名**（Swift，原推荐）：调用处自带说明，同类型实参写反能被发现；用户选了可选，和 C# 一致，调用 .NET 和调用 Nyxel 的规则相同。**只有字面量实参必须写名字**：针对 `SetActive(true)` 这种布尔陷阱，但多一条“什么时候必须写”的规则。
- **支持重载**（C#）：熟悉，但调的是哪一个要看实参类型才知道；和 `init` 不重载的规则也不一致。

## 后果

- 冒号和等号的分工让读者不用看上下文就能分清“这是类型”还是“这是值”。
- 前几轮示例里的命名实参都改成了 `=`（ADR-0008、language-reference）。
- 待定：属性的 `init` 访问器（只能在构造时设置，C# 9 的 `init`，名字和 Nyxel 的 `init` 冲突）；索引器（`list[0]` 这类）；`field` 关键字（C# 14，自动属性的部分访问器带函数体）。
