# ADR-0005: 语法总体风格：现代花括号系

- 状态：已接受
- 日期：2026-10-02

## 背景

语法总体风格是后面所有语法决定的底子。Agent 对一门语言熟不熟，取决于训练数据里见过多少这种代码。最危险的是“只比 C# 差一点”的语言：Agent 会下意识写出 C# 的写法，碰巧能编译但意思不对（ADR-0003 “和 C# 不似是而非”）。所以要么几乎就是 C#，要么和 C# 明显不同、但长得像 Agent 同样熟悉的另一类语言。

和用户对比了同一段敌人脚本的三种写法后选定。

## 决策

走 Kotlin / Swift / Rust / TypeScript 共有的“现代花括号系”形状：

- 代码块用花括号，结构由括号决定，与缩进无关。
- 声明以关键字开头（`let` / `var` / `func` / `class` 这一类，具体关键字见 ADR-0006），看一行的第一个词就知道它声明了什么。
- 类型写在名字后面：`hp: int`。
- 语句以换行结束，不写分号。
- `if` / `while` 的条件不加括号，但后面的块必须有花括号（不存在单语句省略花括号的写法）。

具体关键字、可见性、命名约定、表达式化程度（`if` / `match` 能否作为值）等，在后续 ADR 中逐项定。

## 备选方案

- **C# 近亲**（类型前置、分号、C# 关键字，做减法加少量增强）：C# 程序员零门槛，Agent 的语料最多；但谈不上更现代，而且离 C# 太近：Agent 会把 C# 有而 Nyxel 没有的写法带进来，读者也分不清这段是 C# 还是 Nyxel。
- **缩进系**（Python / GDScript）：最简洁，做游戏的人熟悉（Godot）；但由缩进决定结构是“看不见的规则”，Agent 局部编辑或复制粘贴时缩进错一格，代码仍能编译而含义变了；lambda 和多行表达式写起来别扭。

## 后果

- C# 程序员要适应类型后置和无分号；作为交换，Nyxel 代码和 C# 代码一眼可分。
- 没有分号，换行在什么情况下结束一条语句需要明确规则（例如二元运算符放在行尾时续行）。这是语法分析器设计的一部分，在 language-reference 里写清。
- 示例代码统一用这种风格写。
