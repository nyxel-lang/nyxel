# ADR-0017: 事件（event / emit / 自动绑定的订阅），状态机不加语法

- 状态：已接受
- 日期：2026-10-02

## 背景

第十三轮讨论，游戏专用特性的剩余两项。

- 事件：一个对象宣布“发生了什么”，关心的对象自己订阅，宣布方不用认识订阅方。C# 的 `event` 在游戏里有两个出名的坑：忘了 `-=`，处理函数就会在已销毁的对象上执行、泄漏内存，用 lambda 订阅时甚至没法取消；引擎里长期存在的对象挂着脚本的处理函数，热重载时旧程序集卸载不掉。
- 状态机：AI、角色动作、UI 流程都是“当前处于哪种状态 + 状态之间怎么切换”。要决定的是语言需不需要专门的语法。

和用户逐项对比代码后，三项都按推荐定了。

## 决策

1. **事件写成带参数名的签名，触发用 `emit`**：
   ```nyxel
   public class Slime : Behaviour {
       public event Died(slime: Slime)
       public event HealthChanged(before: int, after: int)

       func Die(self) {
           emit self.Died(slime = self)
           self.Destroy()
       }
   }
   ```
   - `event 名字(参数)`：参数写法同函数参数（名字: 类型），没有返回值，不能有默认值。可以加 `public`、`protected`、`static`；接口里也可以声明事件。
   - `emit 接收者.事件(实参)` 是语句，命名实参同函数调用。没人订阅时什么也不发生，不用判空。处理函数按订阅顺序同步执行；处理函数抛出的异常传给 `emit` 的一方（同 C#）。
   - 只有声明事件的类型能 `emit`，子类也不行（同 C#）。子类要触发，就由基类提供一个 `protected` 方法。
   - 翻译：C# 的 `event`，类型是为它生成的委托（`Slime.DiedHandler(Slime slime)`），C# 代码可以照常 `+=`。`emit` 是 `Died?.Invoke(...)`。
2. **订阅写 `+=` / `-=`，自动绑定在“执行谁的代码”上**：
   ```nyxel
   slime.Died += self.OnSlimeDied               // 绑定 self
   slime.HealthChanged += func(before, after) { // lambda 写在 self 的方法里：也绑定 self
       self.hud.Shake()
   }
   button.Clicked += self.OnClick               // C# / 引擎的事件同样适用
   ```
   - 处理函数是 `对象.方法` 时绑定那个对象；是 lambda 时绑定写它的那个 `self`。绑定对象实现了生命周期接口（ADR-0016 的 `ILifetime`）时，它被销毁后，订阅在下一次触发时自动移除，不再执行。静态函数、没有生命周期的对象，订阅一直保留到 `-=` 或热重载。
   - 和协程是同一个原则：`launch enemy.Burn()` 执行 enemy 的代码，绑定 enemy；`slime.Died += self.OnSlimeDied` 执行 self 的代码，绑定 self。
   - 热重载时，脚本代码做过的所有订阅（包括订阅在 C# / 引擎对象上的）都会被移除，旧程序集才能卸载。
   - `-=` 可以提前取消用 `对象.方法` 做的订阅。对 lambda 写 `-=` 是编译错误：每次写 lambda 都是一个新函数，取消不掉；它会随绑定对象自动移除。
   - lambda 的参数类型从事件签名推断。
   - 翻译：编译器生成一个包装处理函数（检查绑定对象是否还活着），连同 `-=` 的写法一起登记到 Nyxel.Runtime，供自动移除和热重载使用。
3. **方法可以当作函数值**（订阅需要，顺带定）：在需要函数类型的地方（事件订阅、函数类型的参数和变量），`对象.方法` / `类型名.函数` 不带括号就是这个函数本身，同 C# 的方法组转换：`enemies.Select(Slime.Describe)`。在不需要函数类型的地方不带括号写方法名是编译错误，诊断提示“是不是漏了括号”。.NET 的重载按需要的函数类型选择。
4. **状态机不加专门语法**：
   - 状态用 enum 写，每种状态需要的数据放在 case 里（ADR-0008）；在 `Update` 里 `match` 当前状态，`match` 必须覆盖所有情况（ADR-0009），新加状态后漏处理的地方都会报错。
   - 按顺序推进的流程（过场、Boss 阶段）用协程（ADR-0016）。
   - 写了真实脚本之后，如果反复出现同样的样板代码（比如进入、离开状态的回调），先考虑 Nyxel.Runtime 里的库，库不够再考虑语法。

## 备选方案

- 事件声明：**同 C#，`event Died: func(Slime)`，触发写 `self.Died(self)`**：没有新关键字，但参数没有名字（`func(int, int)` 读不出两个 `int` 是什么），触发和普通方法调用长得一样。**不加语法，用库里的 `Signal<T>` 字段**：语言最小，但拿到字段的人都能 `Emit`，C# 看到的也不是事件。
- 订阅：**同 C#，手动取消**：语言不管生命周期，忘写 `-=` 就在已销毁的对象上执行、泄漏内存、卡住热重载，lambda 订阅没法取消。**`Connect` 返回句柄**：lambda 也能取消，但要自己保存句柄，和 C# 事件的写法不同。
- 状态机：**专门的 `machine` / `state` 语法**（进入 / 离开 / 每帧都有固定位置，工具能画状态图）：功能大，只支持一种模型，状态间共享数据、分层、热重载都要另外设计。**Nyxel.Runtime 现在就提供状态机库**：现在就要定 API，但还没有真实脚本可以参考。

## 后果

- 协程和事件的生命周期规则统一成“执行谁的代码，就绑定谁”。引擎集成时只要让对象基类实现一个生命周期接口。
- 自动移除是在下一次触发时才发生的。绑定对象销毁后、事件触发之前，包装函数和它引用的对象仍然被事件源持有，直到那次触发或热重载。
- C# 代码订阅 Nyxel 的事件时，按 C# 的规则走，不会自动移除。
- 待定：事件的访问器（C# 的 `add` / `remove`）；`emit` 时一个处理函数抛异常要不要继续通知其他处理函数。
