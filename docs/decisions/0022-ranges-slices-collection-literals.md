# ADR-0022: 倒序和步长、区间不是值、切片、集合字面量、多维数组

- 状态：已接受
- 日期：2026-10-06

## 背景

第十七轮讨论，接着逐个讨论 language-reference 各节的“待定”。这一轮是区间与集合：

- 循环一节的“区间作为值和切片”“步长、倒序”；
- 数组一节的“多维数组”“带元素创建（集合字面量）”“C# 的初始化器”。

C# 8 的范围下标（`name[1..3]`、`items[^1]`）和 C# 12 的集合表达式（`[1, 2, 3]`、`[..a, ..b]`）都和 Nyxel 的区间写法 `..<`、`...` 有交集，所以放在一起定。八项分两批和用户对比了代码，都按推荐定。

## 决策

1. **倒序和步长：区间后面接 `.Reversed()`、`.StepBy(n)`**，只用在 `for` 里。
   ```nyxel
   for i in (0..<self.enemies.Count).Reversed() {     // Count-1, ..., 1, 0
       if self.enemies[i].IsDead {
           self.enemies.RemoveAt(i)
       }
   }
   for x in (0..<width).StepBy(2) { ... }             // 0, 2, 4, ...
   ```
   - 边界和正着遍历一样，不用自己算 `Count - 1`。编译器翻译成普通的 `for`，不分配。
   - 叫 `Reversed()` 不叫 `Reverse()`：.NET 的 `list.Reverse()` 把 List 原地倒过来；过去分词表示“给我倒过来的一份”，同 Swift、Kotlin。
   - 叫 `StepBy(n)` 不叫 `Step(n)`：游戏代码里 `Step()` 通常是“推进一步”（物理步进）。
   - 步长必须是正数。两个可以连用，按书写顺序生效：`(0..<10).StepBy(4).Reversed()` 是 8、4、0，`(0..<10).Reversed().StepBy(4)` 是 9、5、1。
2. **区间不是值**。只能写在三个地方：
   - `for ... in` 后面（可以接 `.Reversed()`、`.StepBy(n)`）；
   - `case` 后面；
   - 切片的 `[ ]` 里。

   `let r = 0..<10`、把区间传给函数都是编译错误。判断在不在区间里用 `match` 的 `case 1...3`，或者 `x >= 1 and x <= 3`。
3. **切片同 C# 8 的范围下标**，写法用 Nyxel 的区间：
   ```nyxel
   let prefix = name[0..<3]        // 前 3 个字符（C# 的 name[0..3]）
   let middle = items[2...4]       // 第 2、3、4 个（C# 的 items[2..5]）
   let rest = name[1...]           // 从第 1 个到末尾（C# 的 name[1..]）
   let head = items[..<3]          // 从开头到第 3 个之前（C# 的 items[..3]）
   ```
   - 只有切片能省略一边：省略开头写 `..<b` 或 `...b`；省略结尾只写 `a...`，没有 `a..<`（到末尾没有“含不含”的区别）。同 Swift。
   - 能切的类型和结果同 C#：字符串得到新字符串，数组和 List 复制出新的一份（分配），`Span` 只指向原来的那一段。
4. **没有从末尾数的 `^`**。最后一个写 `items[items.Count - 1]`，去掉末尾 4 个字符写 `path[..<path.Length - 4]`。`^` 只是异或。
5. **集合字面量 `[1, 2, 3]` 同 C# 12 的集合表达式**：
   ```nyxel
   let primes: array<int> = [2, 3, 5, 7]
   var enemies: List<Enemy> = []
   self.Patrol(points = [self.a, self.b, self.c])
   for dir in [Dir.Up, Dir.Down] { ... }
   ```
   - 集合的类型来自期望的类型：声明的类型、参数类型、返回类型。数组、List、Span、`IEnumerable<T>`、`IReadOnlyList<T>` 等 C# 12 支持的类型都可以。元素按元素类型处理，同数字字面量的规则。
   - 没有期望的类型是编译错误：`let xs = [1, 2, 3]` 要写成 `let xs: List<int> = [1, 2, 3]`。
   - 例外是 `for x in [a, b]`：马上被遍历的值不需要写类型（同元组“直接被解构的值不需要名字”，ADR-0021），元素类型取元素的共同类型。编译器把它放在栈上，不分配。
   - 元素是元组、`for` 又把它解构时，元组也不用写名字：`for (dx, dy) in [(0, 1), (1, 0)]` 的每个元组马上被拆开，算“直接被解构”（讨论第 3 轮后用户确认）。
   - 可以换行写，末尾可以多一个逗号。
   - C# 的集合初始化器 `new List<int> { 1, 2 }` 是编译错误，提示写 `[1, 2]`。
6. **集合字面量里没有展开**（C# 12 的 `[..a, ..b]`）。先创建，再 `AddRange`。
7. **字典字面量暂不支持**。先创建，再逐个 `prices["sword"] = 100`。C# 正在设计字典表达式（提案写法 `["sword": 100]`），等它发布再讨论。
8. **多维数组写 `array2d<T>`、`array3d<T>`**，就是 .NET 的 `T[,]`、`T[,,]`。
   ```nyxel
   let grid = new array2d<Tile>(width, height)
   grid[x, y] = Tile.Wall
   for x in 0..<grid.GetLength(0) { ... }
   ```
   - 创建时按位置写各维的长度；下标 `grid[x, y]`；`GetLength`、`Length` 等成员同 .NET。
   - 最多三维。`array2d`、`array3d` 和 `array` 一样是关键字，不能当名字用。
   - C# 的 `T[,]`、`new T[w, h]` 是编译错误，诊断给出 `array2d<T>` 的写法。
   - 多个下标 `a[i, j]` 同样用于 C# 有多个参数的索引器，比如 `Matrix4x4[row, column]`。

## 备选方案

- **倒序：Kotlin 的 `n - 1 downTo 0`、`0..<n step 2`**。坏处：要自己算 `Count - 1`，多两个关键字。
- **倒序：区间写反就倒着走（`count - 1 ... 0`）**。坏处：`count` 为 0 时 `0 ... -1` 本该一次不走，却会走 0 和 -1 两次。Kotlin、Rust 把它当空区间，Swift 运行时报错。
- **区间是值**（Kotlin 的 `IntRange`、Swift 的 `Range`）。
  - 好处：能存、能传、能 `Contains`、能当 LINQ 序列。
  - 坏处：.NET 的 `System.Range` 是切片用的下标范围，不能有负数，也不能遍历；要在 Nyxel.Runtime 里另造一个类型，出现在公开 API 里时 C# 调用方也得认识它。目前的用法 for、case、切片都覆盖了。
- **切片只允许字符串和 Span**。
  - 好处：数组、List 的切片会悄悄复制，而 Swift、Go、Rust 的切片和原来共用内存，从那边过来的人可能以为改切片会改到原来的。
  - 坏处：游戏脚本里很少切数组，多一条“哪些类型能切”的规则不划算。
- **不要切片，用 `Substring`、`GetRange`**。坏处：第二个参数是长度不是终点，`Substring(2, 5)` 取的是第 2 到第 6 个，是 C# 里常见的错误。
- **`^1` 同 C#**。坏处：游戏代码里少见，读的人要学新符号；`^0` 是“最后一个之后”，当下标越界，容易弄反；`^` 同时是异或。
- **没有期望的类型时，集合字面量默认是 `List<T>`**（Python、Swift 的习惯）或 **`array<T>`**。坏处：`let xs = [1, 2, 3]` 看不出能不能 `Add`。C# 团队也讨论过默认 `List<T>`，还没定；现在报错，将来可以放开。
- **展开同 C# 12 的 `..xs`**。
  - 好处：短，Agent 顺手。
  - 坏处：`[..bosses]` 和切片 `items[..<3]` 长得像，意思完全不同；在字面量里拼接集合在游戏脚本里不常见。`..` 现在只用来报错，以后要加不影响已有代码。
- **字典字面量用冒号 `["sword": 100]`**（Swift、C# 的提案）。坏处：Nyxel 里冒号后面是类型（ADR-0011），键是变量时 `[fire: 2.0]` 像在声明。
- **字典字面量用等号 `["sword" = 100]`**。坏处：读起来像赋值，可能和 C# 将来的写法不同。
- **多维数组不支持，用数组的数组或一维数组换算下标**。坏处：数组的数组要逐行创建，一维数组要自己算 `y * width + x`，都容易写错；.NET API 返回的 `T[,]`（比如地形高度图）写不出类型。
- **多维数组写 `array<T, 2>`**。坏处：C++ 的 `std::array<int, 2>` 是“长度为 2 的数组”，读者会理解错。

## 后果

- 下面几项还没定，记在 language-reference 的“待定”里：
  - 区间当值：以后有需要再讨论，放开不影响已有代码。
  - 展开 `..xs`、字典字面量（等 C# 的字典表达式发布）。
  - 带元素创建多维数组（C# 的 `new int[,] { { 1, 2 }, { 3, 4 } }`）。
  - C# 的对象初始化器 `new Enemy { Hp = 10 }`：C# 里只能在构造时设置的属性靠它设置，和 `init` 访问器一起讨论。
- 特性（C# 的 `[Serializable]`、`[Obsolete]`）还没讨论过，roadmap 记在 M3 的待定里。集合字面量用了 `[`，特性要不要也用方括号，到时候再比较。
- 分工：
  - Parser：区间能写在哪里、哪些能省略一边、`for` 里只接 `Reversed()` / `StepBy(n)`；集合字面量；`array2d` / `array3d`；C# 写法（`..`、`^`、展开、字典项、`T[,]`、`new T[w, h]`）的诊断。区间的位置在整棵树建好以后检查，那时每个区间能看到它在哪里。
  - 语义分析（M2）：集合字面量的期望类型、`for` 里字面量的元素类型、步长是正数、切片的类型能不能切。
  - 降级（M2）：`Reversed()` / `StepBy(n)` 翻译成普通的 `for`；`for` 里的字面量放在栈上；`a...b` 切片翻译成 C# 的 `a..(b + 1)`。
- 错误码见 design/diagnostics.md。
