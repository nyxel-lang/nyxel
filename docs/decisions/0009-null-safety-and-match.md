# ADR-0009: 空值安全与 match

- 状态：已接受
- 日期：2026-10-02

## 背景

第五轮讨论：“可能没有”（空值）和“几种情况之一”（模式匹配）。空值引用是游戏脚本里最常见的崩溃来源（目标死了、组件没挂、场景里找不到对象）。C# 8 的可空引用类型把“可能为 null”写进了类型，但违反只给警告，照样编译、照样崩。和用户逐项对比代码后选定。match 这一项，用户提出：能否复用 `->` 而不再引入 `=>`；按名字取数据时用 `:` 改名（`case Heal(amount: healed)`）和声明里的 `名字: 类型` 形状相同、含义不同，容易混淆。两点都采纳了。

## 决策

1. **可空性是类型的一部分，违反是编译错误**。
   - `T` 一定有值，`T?` 可能是 `null`。值类型的 `int?` 与 C# 相同。
   - 使用 `T?` 的成员、把 `T?` 传给 `T`，都是编译错误，诊断给出检查的写法。
   - 不可空的字段必须确定初始化（ADR-0008）。
   - 与 .NET 互操作：C# 程序集上的可空标注照单全收；没有标注的程序集，返回值和字段一律当作 `T?`，参数当作可以接受 `null`。
2. **检查后自动收窄**（C# / Kotlin 的流分析）。
   - `if x != null { ... }` 的块里、`if x == null { return }` 之后，`x` 当作非空。
   - 只对局部变量和参数收窄。字段、属性、调用结果要先存进局部变量，因为在检查和使用之间它们可能被别处改掉。给 `var` 局部变量重新赋值后，收窄失效。
3. **运算符**：`?.` 和 `??` 与 C# 相同。`??` 的右边除了值，还可以是 `return`（可带返回值）、`throw`、`continue`、`break`：`let target = self.FindTarget() ?? return`。
4. **没有强制解包运算符**（没有 `x!` 和 `x!!`）。断言非空写 `?? throw new 异常类型("失败原因")`。
5. **match 的分支**：
   ```nyxel
   let change = match hit {
       case Physical(amount) -> -amount
       case Burn(amount, seconds) -> -amount
       case Heal(amount) -> amount
   }
   ```
   - 每个分支一行，以 `case` 开头，和 enum 的声明逐行对应；默认分支写 `else`。
   - 分支用 `->`，和函数返回类型共用同一个箭头，含义都是“左边得到右边”。Nyxel 里没有 `=>`。
   - 分支的右边是一个表达式或一个块；`match` 当表达式用时，块的值是它最后一个表达式（ADR-0007）。
6. **按字段名取出 case 的数据**。
   - `case Burn(seconds)` 取出名为 `seconds` 的那一项，作为这个分支里的局部变量；可以只列需要的字段，顺序无关；不需要数据时可以不写括号：`case Physical`。
   - 不支持改名。取出的名字和已有的局部变量或参数重名时编译报错，提示给外面的变量改名。
7. **match 必须覆盖所有情况**，当语句用时也一样（参照 Swift）。对 enum 要列全所有 case 或写 `else`，缺了就报错，诊断列出缺的 case。对其他类型必须有 `else`。“其余不处理”写 `else -> {}`。

## 备选方案

- **违反只给警告**（同 C#）：照样编译，运行时照样崩，Agent 生成的代码没有编译器把关。**没有标注的 .NET API 当“平台类型”不检查**（Kotlin）：用老库方便，但那部分代码重新失去保护。现在 .NET 自身的库和引擎脚本 API 基本都有标注，用不到 Kotlin 那样的折中。
- **Swift 的 `if let` / `guard let`**：显式绑定一个非空的新名字，但要多两个专门的语法结构；流分析的写法和 C# 程序员本来就写的 `if x != null` 一样，含义也一样。
- **`x!!`（Kotlin）**：简短，但没有失败原因，容易被随手加上让编译器闭嘴。**`x!`（Swift）**：为 null 时抛异常，而 C# 的 `x!` 只是关掉警告、运行时不检查，同一写法含义不同。
- **match 分支用 `=>`**（C# switch 表达式、Rust）：熟悉，但语言里会有 `->` 和 `=>` 两个箭头。Kotlin 的 `when` 和 Java 14 的 `case X -> ...` 都用 `->`。
- **分支不写 `case`、默认分支用 `_`**（Rust、Kotlin）：更简洁，但每行不再以关键字开头，数据按位置取：两个同类型的字段写反了编译器发现不了。**C# 式类型模式**（`Damage.Burn b => b.Seconds`）：和 C# 最像，但要多一个变量名，分支用逗号分隔。
- **用冒号改名**（`case Heal(amount: healed)`，Rust / Swift 的写法）：和 Nyxel 声明里的 `名字: 类型` 形状相同、含义不同（用户指出）。**用 `as` 改名**：C#、Kotlin、Swift、Rust 的 `as` 都是类型转换，Nyxel 以后很可能也要用 `as` 做转换。改名只在重名时需要，先不支持，以后真需要再加一种不用冒号的写法，不会破坏已有代码。

## 后果

- 写 C# 习惯的 Agent 会写出 `x!`、`=>`、不检查就用 `T?`，都会得到编译错误和明确的修改提示。
- 流分析要在语义分析阶段实现（和确定初始化检查共用数据流框架）。
- 待定：数组元素的默认值（`new Enemy[10]` 的元素是 null，C# 也有这个漏洞）；`x == null` 翻译成 C# 的 `== null` 还是 `is null`（引擎对象可能重载了 `==`，比如 Unity 的“已销毁对象等于 null”）；`??=`；常量、比较、类型模式与 guard（下一轮）；带数据 case 在 C# 那边的属性名大小写。
