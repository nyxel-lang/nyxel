# ADR-0013: 默认 init 与 super、混合运算的字面量定型、续行

- 状态：已接受
- 日期：2026-10-02

## 背景

第九轮讨论。写 samples/ 时暴露了三处 ADR-0005 到 0012 没覆盖的规则：

- 继承 `Behaviour` 的脚本都没写 `init`。引擎通过反射调用无参构造函数来创建脚本，所以需要规定没写 `init` 的类怎么办，以及怎么调用基类的 `init`。
- `slime.Speed = 2 + self.Wave * 0.5`（`Wave` 是 `int`，`Speed` 是 `float`）按 ADR-0007 的说法不明确。
- 方法链写成多行时，换行算不算结束语句。

和用户逐项对比代码后，四项都按推荐定了。

## 决策

1. **没写 `init` 的类自动有一个公开的无参 `init`**（同 C#、Swift、Kotlin）。
   - 前提是每个字段都有初始值，否则编译错误，诊断要求写 `init`。
   - 声明了任何 `init`（不论带不带名字）就不再自动生成。
   - 自动生成的 `init` 是公开的，这是“成员默认私有”的例外：它的用途就是让别人（引擎）创建对象。
   - struct 同样处理。声明了 `init` 的 struct 不能写 `new Health()`（C# 允许，得到全零的值）。
2. **调用基类 `init` 写 `super.init(...)`，只能是 `init` 的第一句**：
   ```nyxel
   public init(power: int, radius: float) {
       super.init(power = power)
       self.Radius = radius
   }
   ```
   - 没写时自动调用基类的无参 `init`，基类没有无参 `init` 就是编译错误。
   - 参数里不能用 `self`：这时对象还没构造好。
   - 本类 `init` 之间委托写 `self.init(...)`，同样只能是第一句。委托了的 `init` 不再调用 `super.init`，确定初始化检查以被委托的 `init` 为准。
   - 重写的方法里调用基类方法写 `super.Update(dt = dt)`。
   - 翻译：`super.init(...)` 是 C# 构造函数头部的 `: base(...)`，`self.init(...)` 是 `: this(...)`，`super.Update` 是 `base.Update`。
3. **混合运算里字面量的类型：期望类型往里传，但不改变整数运算**（补充 ADR-0007 决策 3）：
   1. 运算的一边是有确定类型的值（变量、字段、属性、函数调用的结果）时，字面量跟着它：`width * 0.5` 是 `float`；`self.Wave / 2` 永远是整数除法。
   2. 一边是整数值、另一边是小数字面量时（`self.Wave * 0.5`），这次运算按浮点算：外面期望的类型是浮点类型就用它，没有期望类型时用 `double`（同 C#）。期望的类型是整数时编译错误。
   3. 两边都是字面量时，看外面期望的类型：`let x: float = 1 / 2` 是 0.5。没有期望类型时 `int` / `double`。
   4. 期望的类型来自：赋值目标、声明的类型、参数类型、返回类型、比较运算的另一边；经过算术运算符向里传给两边。
4. **续行：运算符放行首**。
   - 圆括号、方括号里的换行不结束语句。
   - 下一行以 `.`、`?.` 或二元运算符（包括 `and`、`or`、`??`、`is`）开头时，接着上一行。语句不可能以二元运算符开头（单独的 `-x` 不是合法语句，同 C#），所以没有歧义。
   - 一行以 `=` 或 `->` 结尾时，接着下一行（长初始值、`match` 分支、表达式体函数）。
   - 其余换行都结束语句。二元运算符写在行尾是编译错误，诊断提示挪到下一行开头。
   - `{` 必须和它前面的内容（`if` 条件、函数签名等）在同一行，`else` 必须跟在 `}` 后面同一行。

## 备选方案

- 默认 `init`：**每个能创建的类都必须显式写 `public init() { }`**：没有看不见的规则，但每个脚本多一行样板。自动生成是 C#、Swift、Kotlin 共同的做法，Agent 不会意外。
- 基类调用：**写在参数列表后面**（C# 的 `: base(...)`、Kotlin、Dart）：一眼看出不是普通语句，但冒号后面是一次调用，打破了 ADR-0011 的“冒号后面是类型”，也容易和返回类型混淆。**关键字用 C# 的 `base`**：C# 程序员更熟，但 Nyxel 用的是 Swift 的 `self`，`self` / `super` 配套；ADR-0006 规定拿不准时参照 Swift。**Swift 的顺序**（先给自己的字段赋值，最后调 `super.init`）：.NET 规定先构造基类，而 Nyxel 经 C# 编译，`super.init` 只能翻译成构造函数头部的 `: base(...)`。
- 字面量：**只看相邻操作数**（C# 的局部规则）：最简单，但游戏里常见的“整数乘小数再赋给 float”会报错。**期望类型传给所有字面量**（Swift 式）：Swift 没有 `int` 到 `float` 的隐式转换所以没问题；Nyxel 有（ADR-0010），于是 `self.Speed = self.Wave / 2` 按浮点除得 1.5，`let h = self.Wave / 2` 按整数除得 1，同一个式子放的位置不同结果不同。
- 续行：**运算符放行尾**（Go）：词法分析最简单，但方法链要把 `.` 写在行尾，和 C# / LINQ 的习惯相反。**行首行尾都行**（接近 Swift）：同一件事两种写法，违反 ADR-0003。**只有括号里能换行**（Python）：规则最少，但方法链和长条件都要多套一层括号。JavaScript 的自动补分号、Kotlin 把行首 `+ bonus` 当成新语句，都是续行规则含糊造成的静默错误。

## 后果

- samples 里的脚本类不写 `init` 就能被引擎创建。
- 字面量定型需要在语义分析时把期望类型从外往里传，和 ADR-0007 的后果一致。和 C# 不同的只有两类：C# 会报错的混合运算（`2 + self.Wave * 0.5` 赋给 `float`），以及纯字面量运算（`let x: float = 1 / 2`，C# 得 0）。
- 续行规则在词法 / 语法分析里实现：词法分析照常产生换行记号，语法分析在“下一行以 `.` 或二元运算符开头”“上一行以 `=` / `->` 结尾”“在圆括号或方括号里”时跳过换行。
- 待定：调用基类的命名 `init` 的写法。显式数字类型转换后来定为 `x as T`（ADR-0014）。
