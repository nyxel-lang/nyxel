# ADR-0006: 声明：可变性、类型标注、函数、可见性、命名、关键字风格

- 状态：已接受
- 日期：2026-10-02

## 背景

ADR-0005 定了现代花括号系的总体风格。这一轮定最常写的声明：变量和字段、函数、可见性、命名，以及以后新增关键字都要遵守的风格规则。和用户逐项对比代码后选定。

## 决策

1. **可变性**：`let` 声明不可变，`var` 声明可变，局部变量和字段都用这一对。不可变的是名字本身，不是它指向的对象：`let enemies = new List<Enemy>()` 之后不能让 `enemies` 改指别的列表，但可以 `enemies.Add(e)`（相当于 C# 的 readonly）。struct 变量存的是数据本身，所以 `let` 的 struct 整个不可变（ADR-0008）。`let` 字段只能在声明处或构造过程中赋值。给 `let` 重新赋值是编译错误，诊断要建议改用 `var`。
2. **类型标注**：类型写在名字后面。字段、函数参数、返回类型必须写；函数内部的局部变量有初始值时可以省略，由编译器推断。
3. **函数**：`func Name(a: A, b: B) -> R { ... }`。没有返回值时省略 `-> R`。实例方法和静态函数怎么区分见 ADR-0008（参数里的 `self`）。
4. **可见性**：成员默认私有，公开的写 `public`，含义与 C# 相同。`protected`、`internal` 等更细的级别用到时再加。类型的默认可见性见 ADR-0008。
5. **命名**：沿用 .NET 约定，由编译器检查，不符合给警告。
   - PascalCase：类型、方法（无论可见性）、属性、`public` 字段。
   - camelCase：参数、局部变量、非公开字段（不加前缀，ADR-0008）。
   - 调用 .NET API 时名字原样使用，生成的 C# 不改名。
6. **关键字风格**：关键字用完整英文单词；只有在主流语言里已经通用、而且能读出来的缩写可以例外（`var`、`func`、`enum`、`struct`）。不用 `fn`、`pub`、`mut`、`impl` 这类符号式缩写。

`let` / `var` 加 `func` 加 `->` 是 Swift 的写法组合。语法定不下来的细节，优先参照 Swift 的做法，让 Agent 有一套一致的参照。

## 备选方案

- 可变性用 `val` / `var`（Kotlin）：两个词只差一个字母，读的时候容易看错。用 `let` / `let mut`（Rust）：可变最显眼，但会让人联想到 Nyxel 没有的 Rust 借用规则。
- 函数用 `fn`（Rust）：最短，但它是这套关键字里唯一读不出来的缩写，和 `public`、`let`、`var` 的风格不一致，也和上面选 `public` 不选 `pub` 冲突（用户指出）。用 `fun ... : R`（Kotlin）：返回类型的冒号和参数的冒号混在一起。用 `function`：完整单词，但没有主流语言是 `function` 配 `->` 的组合，函数行也最长。
- 返回类型用冒号 `: R`：冒号统一表示“的类型是”，但在 `func F(a: int, b: float): int` 里最后一个冒号容易看成参数的一部分。箭头把输入和输出分开，函数类型也能写成 `(A, B) -> R`，用同一个符号。
- 可见性用 `pub`：含义相同，更短，但手写省事是最低优先级。默认公开、写 `private` 隐藏（Kotlin）：不写就暴露，读者分不清公开是不是有意的。
- 命名用 camelCase 成员并自动映射成 .NET 的 PascalCase（Kotlin 风格）：Nyxel 内部统一，但映射是看不见的规则，拿名字去搜 C# 文档对不上，C# 里看到的名字也和源码不同。不规定命名：灵活，但 Agent 输出的风格会漂移。

## 后果

- 公开 API 的形状一眼可见：扫 `public` 就知道类对外暴露了什么，字段和函数签名的类型都写全了。
- 编译器要有命名检查（警告），给出改名建议。
- 函数类型的写法随 lambda 一起定，倾向同样用 `->`。
