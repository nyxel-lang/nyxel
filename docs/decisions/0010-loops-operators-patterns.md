# ADR-0010: 循环、区间、运算符与其余模式

- 状态：已接受
- 日期：2026-10-02

## 背景

第六轮讨论：循环、数字区间、逻辑运算符、`++` / `--`，以及 ADR-0009 之外的匹配模式。和用户逐项对比代码后选定。

## 决策

1. **循环**：
   - `for 名字 in 集合 { ... }` 遍历；循环变量不可变（相当于 `let`）。
   - `while 条件 { ... }`。
   - 没有 C 风格的三段式 `for`，没有 `do` / `while`。
   - `break` / `continue` 同 C#。
2. **区间**：
   - `a..<b` 不含 `b`，`a...b` 含 `b`（Swift 的写法）。没有单独的 `..`。
   - 遍历整数区间翻译成 C# 的普通 `for` 循环，不分配内存。
3. **逻辑运算符用单词**：`and`、`or`、`not`，代替 `&&`、`||`、`!`。短路求值和优先级（`not` > `and` > `or`）同 C#。`!=` 保留。写了 `&&`、`||`、`!` 是编译错误，诊断给出对应的单词。
4. **没有 `++` 和 `--`**，写 `i += 1`。复合赋值 `+=` 等同 C#。
5. **其余运算符同 C#**：算术、比较、位运算（`&` `|` `^` `~` `<<` `>>`）的写法和优先级；整数相除向零取整；C# 允许的隐式数值转换（如 `int` 到 `float`）。
6. **match 的其余模式**：
   - 常量：`case 0`、`case "boss"`、`case null`。
   - 比较：`case < 10`（`<` `<=` `>` `>=`）。
   - 区间：`case 10..<50`、`case 1...3`。
   - 组合：`case 1 or 2`、`case > 0 and < 10`、`case not null`，和逻辑运算符是同一套单词。
   - 附加条件：`case Burn(seconds) when seconds > 3`，`when` 的含义同 C#。
7. **类型检查与收窄**：
   - `x is Enemy` 得到 bool，同 C#；`x is not Enemy` 是它的否定。
   - 被检查的如果是局部变量或参数，它会被收窄（和 ADR-0009 的空值收窄是同一条规则）：`if other is Enemy { ... }` 的块里、`if other is not Enemy { return }` 之后、`match other { case is Enemy -> ... }` 的分支里，`other` 当作 `Enemy`。
   - 不另起变量名。
   - `is` 后面只能写类型。数值比较等其余模式只用在 `match` 里，这样同一件事只有一种写法：`if hp < 10`，而不是 `if hp is < 10`。

## 备选方案

- **区间用 `..` / `..=`**（Rust；C# 的 `..` 也不含终点）：和 C# 同写法同含义，但 Kotlin 的 `0..10` 含终点，读者会理解反。`..<` 把“小于”写在符号里，谁读都不会误解。**保留 C 风格 `for` + `foreach`**：最像 C#，但三段式循环容易写错边界。
- **`&&` / `||` / `!`**（C#）：所有 C 家族语言都这么写，但 `!` 很细，容易看漏；而且模式里还得另用 `and` / `or` / `not`（C# 自己就是两套写法）。
- **`++` / `--` 只能作为独立语句**（Go）：保留了熟悉的写法，但多了一条“哪里能写”的规则。**同 C# 保留前置和后置**：`i++` 和 `++i` 的区别是经典陷阱。
- **类型模式另起名字**（C#：`case Enemy enemy`、`if other is Enemy enemy`）：对任何表达式都能用，但多一个名字。和 ADR-0009 的“不另起名字、局部变量自动收窄”不一致；要匹配表达式时先存进局部变量，规则和空值相同。

## 后果

- 写 C# 习惯的 Agent 会写出 `&&`、`!`、`i++`、`foreach`、`0..10`、`is Enemy e`，都会得到编译错误和明确的修改提示。
- 类型收窄和空值收窄共用一套流分析。
- 待定：赋值是语句还是表达式（C# 里 `a = b = c` 合法）；带标签的 `break`；区间作为值和切片（`list[0..<3]`）；步长和倒序；遍历时同时拿到下标；`x is 某个 enum case`。
