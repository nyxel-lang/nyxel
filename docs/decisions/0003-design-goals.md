# ADR-0003: 设计目标：Agent 生成与人读优先

- 状态：已接受
- 日期：2026-10-02

## 背景

用户对语言的要求：方便 Agent 生成、方便真人阅读；真人编写的便利程度可以降低优先级；语法要更现代。语言的使用场景是游戏控制脚本，运行在 native 引擎宿主的 CLR 里，要和 C# 互操作。

传统语言设计里"写起来顺手"占很大比重：缩写、隐式规则、同一件事的多种写法，都是为了少敲键盘。代码主要由 Agent 生成时，这部分收益变小，代价却还在：写法多，Agent 的输出就不稳定，读者要认的形式也多；隐式规则越多，读代码时越要在脑子里补全看不见的东西。

## 决策

评价任何语言特性时，按下面的优先级取舍，排在前面的优先：

1. **读者能正确理解**：人和 Agent 读到代码，不需要上下文就能知道它做什么。
2. **Agent 能一次写对**：能在编译期发现的错误不留到运行时；诊断信息说清在哪、为什么、怎么改。
3. **和 .NET / C# 互操作无缝**：调用 C# 库、被 C# 调用都不需要胶水代码。
4. **每帧运行的游戏代码性能够用**：不为语法便利引入隐藏的分配和间接调用。
5. **手写省键**：最低优先级。

由此得出的准则，在讨论具体语法时用作检查清单：

- **一件事一种写法。** 等价写法越少，Agent 输出越一致，读者要认的形式越少。
- **声明以关键字开头。** 看一行的第一个词就知道它声明了什么，也方便搜索。
- **边界处显式。** 函数签名、公开成员的类型写全；函数内部的局部变量可以推断。
- **不靠看不见的规则改变含义。** 少用隐式转换、容易记错的优先级、由缩进决定的结构。
- **和 C# 不似是而非。** 与 C# 写法相同的代码含义也相同；含义不同就写法不同，免得 Agent 把 C# 的习惯带进来，写出能编译但意思不对的代码。
- **工具输出机器可读。** 诊断带稳定错误码，CLI 能输出 JSON；格式化器只有一种输出（不提供风格选项）。

具体语法逐项和用户讨论后定，写成 ADR；一轮讨论里相关的几项合成一篇。

## 备选方案

- 以手写便利为先（C#、Kotlin 的取向）：大量语法糖和多种等价写法，对人手写友好，但和用户的要求相反。
- 以学习曲线为先（GDScript、Lua 的取向）：动态类型、少关键字，上手快，但类型错误要到运行时才暴露，Agent 生成的代码没有编译器把关。

## 后果

- 有些代码会比 C# 长，比如公开函数必须写返回类型。
- 格式化器（nyxelfmt）是必需品，越早做越好。
- 每个语法提案都要过上面的准则；feature request 模板里有对应的检查项。
