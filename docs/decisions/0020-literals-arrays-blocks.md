# ADR-0020: 字符与原始字符串、数组类型 array<T>、嵌套类型、单独的块、行尾的复合赋值

- 状态：已接受
- 日期：2026-10-06

## 背景

第十五轮讨论。实现语法分析时碰到七处写法，之前的 ADR 没有定。Parser 先一律报编译错误，因为以后放开不会让已有代码失效；这七处都记在 language-reference 末尾的“待定”里。这一轮逐项对比了代码：

- 数组类型用小写关键字 `array<T>` 是用户提出的。
- 指定长度创建数组时，参数名写不写，用户选了和其他调用一样。
- 其余各项按推荐定。

## 决策

1. **字符字面量写 `'a'`，同 C#**。
   - 单引号里是一个 `char`，也就是一个 UTF-16 码元。转义同字符串：`'\n'`、`'\''`、`'\x41'`。
   - 双引号永远是 `string`。
   - 空的、多于一个码元的（包括 emoji 这类要两个码元的字符）是编译错误。
   ```nyxel
   let parts = line.Split(',')
   if text[0] == '#' {
       return
   }
   ```
2. **小数点开头的小数不允许**：写 `0.5`，不写 `.5`，诊断给出改法。
3. **原始字符串同 C# 11；没有逐字字符串**。
   - 两种形式，里面都没有转义：
     - 单行：`"""text"""`。
     - 多行：`"""` 后面换行，接着写内容各行，结尾的 `"""` 单独占一行。
   - 内容里要出现三个连续的引号时，开头和结尾都用更多引号。
   - 多行字符串的值怎么算：
     - 结尾 `"""` 前面的空白，从每一行开头去掉。
     - 某一行不以这段空白开头是编译错误。只含空白的行可以更短，但必须是这段空白的开头部分。
     - 开头 `"""` 所在行的剩余部分、结尾 `"""` 前的换行，都不算内容。
   - 插值：
     - `$"""` 时插值写 `{x}`。
     - `$$"""` 时插值写 `{{x}}`，单个 `{`、`}` 是普通字符。`$` 有几个，插值就用几个大括号。
     - 格式说明符和对齐同 `$"..."`。
   - `@"..."` 是编译错误，诊断建议改用 `"""`。
   ```nyxel
   let pattern = """\d+\.\d+"""
   let help = """
       用法：
         spawn <kind> [count]
       """
   let json = $$"""
       { "hp": {{self.hp}} }
       """
   ```
4. **数组类型写 `array<T>`**，编译成 .NET 的 `T[]`。
   - `array` 是小写关键字，和 `int`、`string` 一样是保留字。
   - 创建写 `new array<T>(长度)`。参数名 `length` 写不写由调用者决定，同其他调用。
   - `T[]`、`new T[n]` 是编译错误，诊断给出 `array<T>` 的写法。
   - 下标、`.Length`、`for ... in` 同 C#。
   ```nyxel
   var hits: array<RaycastHit> = new array<RaycastHit>(16)
   let slots: array<Item?> = ...    // 元素可能为空
   let maybe: array<Item>? = ...    // 数组本身可能为空
   ```
5. **不能在类型里声明类型**。
   - 类型都写在文件顶层，一个文件里可以有多个类型。
   - .NET 里已有的嵌套类型照常使用：`Environment.SpecialFolder.Desktop`。
6. **语句位置不能单独写 `{ ... }`**。要早点结束一个作用域，或者早点释放 `using` 的资源，就拆成函数（ADR-0015）。
7. **一行以任何赋值运算符或 `->` 结尾时，接着下一行**。赋值运算符指 `=`、`+=`、`-=`、`*=` 等。这扩展了 ADR-0013 里的“`=` 或 `->`”。
   ```nyxel
   self.score +=
       enemy.Reward * self.comboMultiplier
   ```

## 备选方案

- **字符：Swift 的做法**，单字符的字符串放在需要 char 的位置就变成 char。
  - 好处：不用新的引号。
  - 坏处：同一个 `"a"` 有时是 string、有时是 char，多了一条看不见的规则。`Split(",")` 这种 string 和 char 两个版本都有的 API，还得另定规则。
- **`.5`：允许（C#、Kotlin、Go）**。
  - 好处：少敲一个 0。
  - 坏处：多一种写法，点容易看漏，而且 Nyxel 里行首的 `.` 表示接着上一行。
- **字符串：两种都不要**。
  - 好处：规则最简单。
  - 坏处：正则、Windows 路径的反斜杠要写两遍，多行文本只能拼接。
- **字符串：逐字和原始都要（C#）**。坏处是两种写法做同一件事，`@"..."` 能做的 `"""` 都能做。
- **数组：`T[]`（C#）**。
  - 好处：Agent 不用学。
  - 坏处：`Item?[]`（元素可空）和 `Item[]?`（数组可空）只差 `?` 的位置。
- **数组：`Array<T>`（Kotlin）**。坏处是和 .NET 的 `System.Array` 类重名，创建的写法也得另想。
  - 最后选了小写关键字，和 `int`、`string`、`func(A) -> R` 一致：语言内置的类型用小写关键字。
- **长度参数必须写名字**（`length = 16`）。
  - 好处：和 `new List<T>(16)` 分得清，后者是预留容量的空列表。
  - 用户选了和其他调用一致，不另立规则。
- **嵌套类型：允许（C#、Swift、Kotlin）**。
  - 好处：`Slime.State` 读起来清楚。
  - 坏处：要连带定几件事：嵌套类型能不能访问外层的私有成员、能不能用外层的类型参数、在外层里能不能省略外层名。类型都写在顶层时，这些问题都不存在；相关的类型放在同一个文件里就行。
- **单独的块：允许（C#）**。坏处是多一种写法，用处又小。
- **单独的块：`do { }`（Swift）**。坏处是 C# 的 `do` 是 `do { } while` 循环，同一个词含义不同。
- **复合赋值：仍然只有 `=` 可以写在行尾**。坏处是规则多一个例外，长的复合赋值只能在运算符处换行。

## 后果

- 下面几项还没定，记在 language-reference 的“待定”里：
  - **多维数组**（C# 的 `T[,]`）：需要另一种写法，游戏脚本里少见。在那之前，API 返回的多维数组只能存进局部变量（类型靠推断）。
  - **带元素创建数组**（集合字面量 `[1, 2, 3]`）**和 C# 的初始化器 `new T { ... }`**：要和 List、Dictionary 一起讨论；C# 12 集合表达式的展开写法 `..x` 和 Nyxel 区间的 `..<` 有冲突。目前 `new` 后面写 `{ ... }` 是编译错误。
  - **数组元素的默认值**：`new array<Enemy>(16)` 的元素一开始都是 null，仍在“空值”一节待定。
  - **插值的 `{ }` 里换行**：C# 11 允许，Nyxel 目前不允许，`$"..."` 和 `$"""..."""` 都一样。
- Lexer 的字符字面量和原始字符串有和 Roslyn 的对照测试：同一个字面量交给两边，比较值和是否报错。
- 错误码见 design/diagnostics.md。
